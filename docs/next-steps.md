# Next steps to agree with the laboratory

The working prototype establishes one complete workflow using assumptions that should be checked against actual SOPs.

| Decision       | Prototype assumption                         | Why it matters next                                                                      |
| -------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Intake         | One sample belongs to one client and batch   | Real submissions may need multiple containers, aliquots and chain of custody             |
| Test execution | One assigned analyst per sample              | Your lab may assign different tests to different analysts                                |
| Results        | Numeric value and supporting reference       | Actual methods may require replicates, calculations, qualitative results and raw files   |
| Specification  | Illustrative method limits copied at receipt | Controlled method versions and product-specific specifications need a dedicated workflow |
| Review         | Separate analyst and reviewer roles          | Actual responsibilities, review checklists and signature meanings must be defined        |
| Exceptions     | Any OOS history blocks routine approval      | A modeled investigation and disposition workflow is required before operational use      |

## Candidate increments

1. Model one actual paper receipt form and one analytical worksheet using sanitized examples; confirm this glossary with staff.
2. Add controlled method/specification administration and replicate-aware results around that worksheet.
3. Add raw-file provenance and instrument imports that call the existing result workflow.
4. Define investigation, corrective-action and disposition records before introducing exception release actions.
5. Replace demo identities with authenticated users, then design role administration, durable storage, backup/restore and operational controls for shared use.
6. Define requirements, traceability, verification, record retention and validation with laboratory quality staff before considering use for regulated records.

These are candidates, not implemented features or a regulatory checklist. The next workflow to build should come from the actual lab's bottleneck.
