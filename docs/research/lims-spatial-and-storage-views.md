# Do any real laboratory information systems ship a spatial, map-like, or 3D view, and of what — and does any of them visualise workflow state spatially?

**Asked by:** Benchline wayfinder map — explorer/3D-workflow-view ticket (orchestrator dispatch)
**Date:** 2026-09-11
**Status of sources:** Checked primary repositories, official project documentation, and vendor documentation directly. No FDA/ISO regulatory text is implicated by this question, so the currency traps noted for those sources do not apply here. Where I relied on a secondary/search-engine synopsis rather than the primary page itself, I say so explicitly below and flag it as unverified in full.

## Findings

### 1. SENAITE — `senaite.storage`

- Repository: https://github.com/senaite/senaite.storage (add-on to SENAITE LIMS, GPL-2.0, per its own `README.rst` license section — checked the `2.x` branch README directly via raw GitHub content, retrieved 2026-09-11).
- The README's own "Screenshots" section names exactly these views, in this order: **Storage facilities**, **Containers and sample containers**, **Store transition in samples listings**, **Assignment of samples in a container**, **Assignment of samples to multiple containers**. (Source: `senaite.storage/README.rst` at the `2.x` branch, section "Screenshots".)
- Community documentation (SENAITE Community forum thread "Storage / Container Hierarchy") describes the storage model as a hierarchy — e.g. facility → freezer → shelf → container — matching the README's "Storage facilities" / "Containers" screenshots. https://community.senaite.org/t/storage-container-hierarchy/906
- I could not load the actual screenshot images (they are referenced by filename in the README — `storage_facilities.png`, `container_listing.png`, `samples_assignment_to_container.png`, etc. — hosted on GitHub raw content) to confirm with certainty whether "container" rendering is a 2D grid of positions or a plain listing/table. The filenames ("listing", "assignment to container") are suggestive of a table/list-based container view rather than a rendered 3D or spatial grid, but I did not visually confirm pixel content, so I record this as **not fully verified** — see "What I could not establish."
- Sample listing/workflow itself, per SENAITE's own documentation (`senaite.com/docs`), is table-based: the Worksheet view is described in SENAITE's official docs as "a spreadsheet-like table" with "Classic" (by Sample) and "Transposed" (by Analysis) layouts. https://www.senaite.com/docs/next/worksheet-basics — this is workflow presentation, and it is explicitly tabular, not spatial or graphical.
- Sample workflow states themselves (Registered → Sample Due → Received → To be verified → Verified → Published) are documented at https://www.senaite.com/docs/sample-basics.html as a state list governing permissions/actions — again presented as states/table columns, not as a spatial scene.
- I found no reference anywhere in the `senaite.storage` repository, its README, its GitHub releases page, or the SENAITE features page (https://www.senaite.com/features/) to a 3D view of any kind. **Negative finding**: searched GitHub search-engine results for "senaite storage container grid layout screenshot," "senaite 3D," and the project's own features/docs pages; found no 3D rendering, WebGL, or Three.js-style visualisation anywhere in the SENAITE ecosystem.

### 2. OpenELIS Global

- Current active repository: https://github.com/DIGI-UW/OpenELIS-Global-2 (Java/Spring + React). The older `openelisglobal/openelisglobal-core` repository is explicitly marked end-of-life in its own description, per GitHub search result metadata — I did not independently open the repository's own EOL notice, so treat that claim as secondary-sourced only.
- Official capabilities page (fetched directly, https://openelis-global.org/features-and-functionality/, retrieved 2026-09-11) describes "Sample management" as: "Follow every specimen from collection to disposal — aliquots, storage locations, barcode moves, and non-conformity workflows, all logged." This is the only storage-location-related claim on the page. It describes a *logging/tracking* capability in prose, not a spatial or map-type view. No rack diagram, grid view, or 3D rendering is mentioned or depicted anywhere on this official capabilities page.
- I did not find, in this page or in the linked GitHub repository search results, any dedicated storage-location "map" or "rack view" UI component comparable to `senaite.storage`'s container screenshots. **Negative finding**: searched "OpenELIS Global storage location rack view GitHub" and the project's own capabilities page; found storage locations referenced only as a data field/hierarchy (room/device/shelf/rack/box, per search-engine synopsis of secondary pages, not independently confirmed against the OpenELIS source tree) rather than as a rendered visual view. I could not locate primary source code (a specific file/module) implementing any such view, and did not have time/tooling in this pass to clone and grep the OpenELIS-Global-2 repository directly — flagged below as an open item.

### 3. Biobank / specimen-management systems (the "freezer box map" claim)

- **FreezerPro** (Azenta Life Sciences, vendor documentation, https://www.azenta.com/products/freezerpro-sample-management-software and https://www.azenta.com/learning-center/resources/freezerpro-interactive-box-view): vendor's own marketing/product page describes "visually-intuitive, customizable freezer maps" and an "Interactive Box View" with "point-and-click" rearrangement of tubes/vials, "large icons and graphical presentations of boxes." This is vendor material, not independently audited source code — I flag it as **vendor-sourced, not primary/open-source-verified**, since FreezerPro is closed-source. The description is consistent across the vendor's own pages (checked two separate FreezerPro pages on azenta.com, both self-consistent).
- **OpenSpecimen** (open-source specimen/biobank management; documentation at openspecimen.atlassian.net Confluence, which is the project's own hosted documentation): its own documentation and forum describe a "container map view" — "a map of the container with the specimens stored in those, and you can click on any slot to view more details," with configurable per-cell fields and colour-coding by specimen type (OpenSpecimen forum post "New in v8.1 - Color coding in container map view," https://forums.openspecimen.org/t/new-in-v8-1-color-coding-in-container-map-view/1832; feature further described in "New feature in v6.2 - Displaying Container Positions in Hierarchy," https://forums.openspecimen.org/t/new-feature-in-v6-2-displaying-container-positions-in-hierarchy/1447). This is the clearest primary-documentation confirmation found in this scout of a **2D grid/map view of a physical container's slots** in an actively maintained open-source LIMS/biobank system. Note the documentation explicitly states "there is no map view available for dimensionless containers" — i.e., the map view is tied to a container that has defined rows/columns, confirming it is a positional grid, not a freeform or 3D scene.
- I did not independently verify LabKey, Bika (SENAITE's predecessor/fork lineage), LabCollector, or Freezerworks beyond secondary search-engine synopses; the CASRAI guide (https://casrai.org/guides/lab-freezer-inventory-systems) and Freezerworks' own "10 must-have" marketing page came up but I did not fetch them directly, so I do not cite specific claims from them here.

### On question 2 — spatial visualisation of workflow state specifically

- Across every system checked (SENAITE, OpenELIS Global, OpenSpecimen, FreezerPro), the storage/rack/box "map" views found are all **maps of a physical container's fixed slot positions** (row/column grid of a box, freezer, or shelf) — not of workflow stage.
- Workflow state, wherever documented, is presented as **table rows with a status column** (SENAITE Worksheet "spreadsheet-like table," SENAITE Sample listing state field) or as **prose-described logged history** (OpenELIS "barcode moves... all logged"). I found no shipped feature in any of these four systems' own documentation or repositories that arranges samples by workflow stage as lanes/columns in a graphical or spatial scene (kanban-style or otherwise).
- General web search for "LIMS kanban board workflow 3D visualization" returned only generic kanban-methodology explainer content (Kanban Tool, Kanbanzone, Wikipedia "Kanban board," CrelioHealth blog) — none of it primary vendor documentation confirming a shipped kanban-style *sample* board inside a LIMS, and none showing 3D. CrelioHealth's blog post claims a "visual workflow map" but describes a process/rule diagram, not a spatially arranged sample board — and it is CrelioHealth's own marketing blog, not independently verified against their product documentation, so I do not treat this as a confirmed instance either way. **Negative finding**: no primary source found, in any system checked, of workflow state rendered as a spatial/graphical scene (2D or 3D) rather than a table or list.

## What I could not establish

- Whether `senaite.storage`'s "container" screenshots are literally a rendered 2D grid of numbered positions (like OpenSpecimen's confirmed container map) or simply a list/table view named "listing" — I did not load the actual PNG screenshots, only their filenames and the surrounding README prose. This is the single most load-bearing unresolved point for the "shape of the distinction" question, since it is the one candidate case that might blur the line between grid and table.
- Whether OpenELIS Global has a rack/box-position UI component at all, beyond the one capabilities-page sentence about "storage locations" being tracked — I did not clone and grep the `DIGI-UW/OpenELIS-Global-2` source tree for a storage/rack view component, and the capabilities page's marketing prose does not describe a rendered UI.
- Whether any commercial LIMS/biobank product beyond the ones checked here (LabKey, LabCollector, Freezerworks, Bika) ships a spatial workflow view — not investigated in this pass; search results surfaced them but I did not fetch primary documentation for any of the three.
- Whether "Bika Lab Systems" (the GPL-2.0 predecessor SENAITE forked from) had any comparable feature — not investigated; out of scope for this pass given SENAITE is the maintained successor.
- I found no evidence, positive or negative, of a *3D* rendering of any kind (container, workflow, or otherwise) in any of the four systems checked. Every visual "map" found (OpenSpecimen, and per vendor claims, FreezerPro) is described in the sources' own language as 2D grid/box positions, never as a three-dimensional scene.
